# 合并番茄钟 · 实施交底文档

本文档不是数据规范，是给**下一个负责写代码的对话 / agent** 看的交底材料，目的是让实现方不需要用户重新讲一遍需求，就能直接开始写代码。数据层的字段、事件、约束以 `docs/data-layer-spec-v4.1.md` 为唯一权威（`docs/data-layer-spec-v4.md` 是 v4.0 历史存档，已不再有效），本文档只做**索引 + UI/交互意图说明**，两者冲突时以 v4.1 正文为准。

---

## 1. 这是什么功能

清单页 / 今日待办里，把几个**耗时都不到一个番茄的零碎小事**拖到一起，用一段专注时间同时推进，专注结束后每件事各自都记一个完整的有效番茄。

**这是平等的"合并"关系，不是子任务的"母子"关系**：
- 子任务（`Task.parentId`）是已经上线的独立功能，服务的是"一个大任务提前规划拆成几块，每块本身要花好几个番茄"的场景（如"阅读《人类简史》"拆成"读10页" / "整理笔记" / "写读后感"）。这次改动**完全不涉及**子任务机制，不要顺带碰。
- 合并番茄钟服务的是"几件互不相关、单独都不够占一个番茄的琐事，凑在一起用一个番茄解决掉"的场景（如"回复Slack消息" + "订咖啡豆" + "归档笔记"）。

两者可以共存：一个子任务本身也可以被拉进合并组。

## 3. 核心产品规则（给实现者的心智模型速览）

以下是从对话中确认、且已写入 v4.1 的关键行为，实现时必须遵守；细节以 v4.1 对应章节为准：

1. **合并资格红线**：只有**从未有过任何 focus Session 记录**（无论 completed 还是 discarded，无论独立还是合并产生）的任务，才能被合并（新建组或加入已有组）。已经计时过的任务永久不能再被合并。写入前必须校验，不满足直接拒绝。
2. **合并后即与标准任务同级别**：合并组一旦成立，被当成一个整体来编号（`pomodoroIndex` 是这个组第几轮，不是每个成员各自的序号），不存在"组内一个任务第3个番茄、另一个第1个"这种混合进度。
3. **每个成员各自记一个完整有效番茄**，不平分；全局统计只按 Session 实际发生次数算一次（这会导致"各任务加总 > 全局总数"，是设计如此）。
4. **可以跨活动清单 / 今日待办合并**；计时进行中可以往合并组里继续拖入新任务（必须满足第 1 条资格）。
5. **番茄到点、组内还有没做完的任务时**，用户二选一：
   - **结束**：没做完的退出组、回到今日待办独立显示；已做完的留在组里不受影响，组不解散（除非退出后剩余成员 < 2，此时自动解散）。
   - **追加预估番茄**：组保持进行中，预估番茄数 +1，已做完的任务继续留在组里，下一轮只有没做完的会被计入新一轮的专注。
6. **三轮预估用满，或组已经做满 7 个番茄仍未全部完成**：**强制卡住**，不能再追加、不能再开新一轮，必须移出剩余没做完的成员，或者把整组解散，才能解开。这一步要弹出提示（`mergeGroupLimitReached`），但提示本身不解除阻塞。
7. **组内成员支持拖拽调整先后顺序**（一个番茄里先做哪件、后做哪件）。
8. **主动整体解散**（用户随时可以取消整次合并）只清空"合并"这个状态，不改变任务在今日待办 / 活动清单里的归属，也不删除任务。

## 4. UI / 交互意图（草案级别，允许按现有视觉风格调整）

**重要前提（用户已明确）**：本节不是像素级规范。实现时只要求 **延续产品现有的视觉风格和交互语言、保证操作顺畅低阻**，具体的动效、卡片样式、颜色、间距、图标等细节，实现方可以自行判断，不需要逐项确认，完成后拿给用户验收即可。

### 4.1 发起合并
- 清单页 / 今日待办现有的拖拽排序（拖到某行上方/下方）之外，新增"拖到某行**正中间**"的手势，触发合并。
- 合并卡片的视觉呈现，**必须和现有子任务的缩进/树状展示明确区分开**——合并是平等并列关系，不能用父子缩进的视觉语言表达，避免用户把两种关系搞混。
- 把一个"已经计时过"的任务拖向合并目标时，需要有防呆反馈（如禁止放置、提示原因），对应第 3 节第 1 条的资格红线。

### 4.2 计时页
- 从合并卡片启动专注时，计时页需要能看到这次专注对应哪几个任务。
- 专注进行中，允许把满足合并资格的新任务继续拖进来（对应第 3 节第 4 条）。

**已发现的既有代码疑点，交给实现方判断**：[TimerView.jsx:191](../src/ui/TimerView.jsx:191) 现有的"当前子任务"卡片（`TimerSubtasks` 组件），数据来自 [timerViewModel.js:21](../src/ui/timerViewModel.js:21) 的 `timerSubtasks()`，取的是**正在计时任务的 `parentId` 子任务**（`taskViews.subtasksByParentId[displayTask.id]`）。但子任务本身不允许再有子任务（两层封顶），所以只有直接对母任务计时时这张卡片才有内容；如果按子任务"先拆好几块、每块单独计时"的设计意图，用户平时应该是对具体子任务计时，这张卡片理论上大部分时候是空的。这很可能是旧原型"这次专注还捎带了哪些别的小事"的概念，在数据层重建时被临时安在了 `parentId` 上——现在合并番茄钟把这个概念正式立起来了，这张卡片的语义归属大概率应该是**合并组成员**，而不是任务的子任务。实现方需要判断：是把这张卡片改成展示合并组成员，还是保留子任务展示、另做一张合并组卡片，还是两者要不要合并成一套展示逻辑——这个判断没有在对话中最终定论，需要实现时和用户一起确认。

### 4.3 收尾流程
- 到点且组内有未完成任务时，展示"结束 / 追加预估番茄"两个选项（对应第 3 节第 5 条）。
- 组已经达到三轮或 7 个番茄的硬上限时，不再提供"追加预估"选项，只能展示"结束"或"解散"（对应第 3 节第 6 条）。

### 4.4 合并卡片内部
- 支持拖拽调整组内成员的先后顺序（对应第 3 节第 7 条），交互逻辑可以参考现有清单排序的手势。
