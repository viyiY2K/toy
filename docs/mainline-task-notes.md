# 中长期主线任务 · 讨论纪要（草案，待新对话展开设计）

本文档不是数据规范，是"合并番茄钟"这轮对话里顺带聊出来的一个**新话题**的讨论纪要，目的是让你在新对话框展开设计时，不用重新跟 Claude 讲一遍已经聊过的内容。这个话题**还没有定案**，本文档只整理已经明确的点和还开放的问题，不是可以直接照做的规范——真正定稿仍需要新对话把开放问题谈清楚，并写回 `docs/data-layer-spec-v4.1.md`。

## 1. 背景：这是什么

对话过程中，关于"子任务（`parentId`）该不该保留"来回了几轮，最后落地成一个更清楚的产品概念：

- **中长期主线任务**：跨周 / 跨月的大目标，比如"阅读《人类简史》"。
- **今日独立任务**：单天内能做完（7 个番茄以内）的具体任务，比如"读10页"、"整理笔记"、"写读后感"。

这两者之间就是现有 `Task.parentId` 表达的母子关系——**不是新机制，是给已上线的子任务功能一个更准确的产品定位**。

## 3. 已经确认的产品语义

1. **母任务 = 中长期主线任务，子任务 = 今日独立任务**。这套父子关系保留，跟合并番茄钟是两套独立机制、互不影响——一个任务可以同时是某个主线任务的子任务、又是某个合并组的成员（见 `docs/data-layer-spec-v4.1.md` §3.1 关键规则 12）。
2. **主线任务的作用主要在"安排今日计划"这个环节**：让用户在排今天要做什么的时候，能看到自己还有哪些长期目标没顾上，起提醒作用，不是让用户对着主线任务本身计时。
3. **计时页面不展示子母关系**，只展示合并关系：如果当前这次专注没有合并（`Session.taskIds` 长度为 1），计时页就只显示这一个独立任务本身，不需要额外展示"这是哪个主线任务的子任务"这类信息；有合并时才展示合并组成员列表。
4. **今日独立任务需要支持批量编辑，绑定到某个主线任务**——这是新提的需求，目前 `docs/data-layer-spec-v4.1.md` §7.4 `task.reparented` 只定义了单个任务"顶层任务变子任务"的操作，**批量版本目前没有定义**，需要新对话设计。

## 4. 需要处理的既有代码（已发现，交给新对话判断）

`src/ui/TimerView.jsx:191`（`TimerSubtasks` 组件）与 `src/ui/timerViewModel.js:21`（`timerSubtasks()`）：目前计时页"当前子任务"卡片取的是正在计时任务的 `parentId` 子任务列表。按本文档第 3 节第 3 条的结论，这张卡片的用途需要改掉——**不再展示子母关系**，改成有合并时展示合并组成员、没有合并时不展示这类卡片。`docs/merge-pomodoro-plan.md` §4.2 里已经记录了这处代码疑点，但当时"计时页不展示子母关系"这条结论还没确定；新对话可以直接按本文档的结论去改，不用再纠结要不要保留子任务展示这个选项。

## 5. 还开放、需要新对话设计的问题

1. **主线任务在计划页面怎么呈现**：用户提出的草案是"在计划页最顶部、和'计划外紧急'同样的位置，拆分左右两栏展示中长期主线任务"，具体交互、和现有活动清单 / 今日待办的关系都还没设计。
2. **批量绑定 / 编辑独立任务到主线任务**：交互形式（多选后指定主线任务？在主线任务卡片里直接拖入？）和对应的数据写入方式（复用 `task.reparented` 批量化，还是需要新事件）都还没定案。
3. **主线任务本身要不要有自己的进度展示**（比如"阅读《人类简史》已经投入了几个番茄、拆了几个子任务"）——这是 `docs/data-layer-spec-v4.1.md` §3.1 关键规则 12 提到过的原始动机，具体呈现方式待设计。

## 6. 讨论中出现过、但已经排除的方向

- **把 `parentId` 子任务机制和 `splitFromTaskId` 拆分衍生机制合并成一套**：讨论中一度怀疑要不要把"子任务"改造成"拆分衍生"的一种，后来确认**两套机制保持独立、都不动**——`parentId` 对应本文档说的主线任务/独立任务关系；`splitFromTaskId`/`lineageId` 对应任务预估超支后被迫拆分、原任务归档的场景，跟本话题无关，不要在设计主线任务时把两者混起来。
- **删除 `parentId` 子任务功能**：一度被提出，已确认不删除，保留现状。
